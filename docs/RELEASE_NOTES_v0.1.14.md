# Jiadun（价盾）v0.1.14 — 结算可信度闸门与跨平台稳定性预发行

v0.1.14 是基于 v0.1.13 实际使用入口和 Windows 兼容接续的可信度收口预发行版和预览候选。重点是让
“数值碰巧相等”不能掩盖漏行、重复、隐藏、公式缓存或控制范围不明；本版不扩展 CAD、BIM、
ERP 或在线协作等高级功能。

本版仍为 Preview/Prerelease，只适合经过授权的试用、合成回归和脱敏资料验证。没有脱敏
真实黄金案例、四种 Office 真机记录、目标规模性能、签名与公证证据前，不得将本版解释为
正式生产版或任何项目的结算审批、付款、责任或经营结论。

## 本版完成

- A 路径继续从清洗明细汇总，B 路径改为直接扫描不可变 `raw_cells`，两条路径分别记录
  文件、SHA-256、Sheet、物理行号、数据范围和过滤条件；A/B 数值一致不再单独代表范围完整。
- C 路径从源表控制行的原始单元格重新读取，保留原始行列、原值、公式/缓存状态和来源
  Evidence；唯一合计级行、无合计级时页级小计互斥求和和控制值不可用分支按实际规则分别记录。
- 覆盖证明固化原始数据区、有效明细、排除小计、标题、说明/备注、空白、待确认、解析失败、
  最终累计行数及各层金额；重复表头、表头前疑似业务行、多候选表头不能被人工映射静默抹掉。
- `.xlsx` 的公式缓存、筛选、表格范围、合并单元格和隐藏行列继续保留结构证据；`.xls` 因
  `xlrd` 无法完整保留公式/合并/筛选拓扑而降级为“部分解析”，只能预览和人工复核，不能形成充分校核。
- 隐藏行/列自动导入时进入待确认；用户明确给出数据范围后可以重放抽取，旧规范明细不会
  重复追加。人工确认绑定当前操作人、时间、修改前后范围和原因，并吸收当前覆盖证明中的
  可见性闸门；人工范围必须覆盖表头后的全部非空物理行，遗漏尾部明细或控制行时期次和项目摘要
  统一保持“校核不充分”。人工确认不会覆盖重复表头、表头前疑似业务行、解析失败等其它结构风险。
- 正式分析入口固定先做 A/B/C 校核，再做异常检测；任一阶段技术失败都会返回 `fail_closed`，
  异常、匹配和导出不能绕过校核闸门。
- 黄金回归继续采用闭世界比较并新增 `tests/anonymized_golden_cases/` 登记入口和
  `docs/GOLDEN_BASELINE_CHANGELOG_v0.1.14.md` 变更记录；黄金执行器不自动更新基线。
- 继承 v0.1.13 的 Windows 符号链接测试守卫和 demo 跨平台确定性修复，确保无权限环境明确
  跳过并保留原因，ZIP 生成结果可重复。

## 使用限制

原始文件保持只读，缺失金额不会补 0，不可比和待确认项目不会强行匹配。AI（如启用）仅可用于
语义候选和文字解释，不参与金额、数量、税率、最终匹配或正式结论。任何“校核不充分”“有条件
结论”“待补资料”均需由业务人员结合原始 Evidence 继续复核。

## 安装资产

macOS Apple Silicon 预发行资产：`Jiadun-0.1.14-macos-arm64.dmg`。下载后使用同一 Release
中的 `SHA256SUMS.txt` 校验。旧 `costguard` 图形命令、GitHub 仓库地址、历史 tag、旧项目目录
和旧导出文件保留兼容意义；升级不会删除、覆盖或移动原始工程资料。
