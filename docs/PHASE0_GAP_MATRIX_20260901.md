## 结论

当前工作树已经完成 P0-02 四级状态语义、P0-03 不可变 Run Contract 的核心闭环，并建立了 P0-01 逐 Sheet/逐行覆盖证明、当前运行绑定和 P0-04 黄金回归执行器；P2-03 项目版本链和 P2-01 历史综合单价资产也已具备受控核心路径，且已接入 Excel 专用工作表和工作台只读入口。生产化结论仍被以下证据闸门限制：

1. 黄金回归目前只有 1 个合成演示案例，经过脱敏、授权和 SHA-256 核验的真实案例数量为 0；不能把合成数据写成真实项目回归通过。
2. A、B 在共享抽取行集时仍明确标记为非独立；C 控制不可用、范围不完整或有待确认 Sheet 时，期次只能是“校核不充分”。真实项目的完整范围证明和反例库仍需补齐。
3. WPS macOS、WPS Windows、Microsoft Excel macOS、Microsoft Excel Windows 真机记录，以及 1 万/5 万/20 万行完整现场性能报告、签名/公证和异常退出恢复证据尚未形成当前发布闭环。

因此，当前版本可以继续进入 P0-04/P0-06 的工程化建设，但只能标记为预览/Beta 候选，不能标记为正式生产版。P1/P2 功能必须继续服从状态、Evidence、Run Contract 和 fail-closed 边界。

本轮增量已补充运行级和资产级边界：人工确认完成后在最后一条 Audit 写入后形成最终 Run Contract，并将本次 Evidence/Audit/匹配快照重绑到该运行；Finding 的数据库触发器要求状态变化同时存在 Evidence、Audit 和不可变状态事件；项目级别名强制只能写入调用方项目；项目版本以不可变清单快照保存送审、补充、复审和审定链，历史综合单价只能从“已关闭且绑定最终审定版本”的快照采集，缺失单价不补零，跨地区/时间/专业维度不齐时返回“不可直接比较”。v39 将原始网格改为不可改写/删除的证据根，v40 增加版本快照字段、显式来源单元格和历史单价资产字段的来源勾稽，v41 补充版本来源 Sheet 的期次/文件关系，v42 保护原始网格尺寸/布局和已确认表头免遭直接更新，v43 保护源文件身份并拒绝写入超出 Sheet 声明网格的原始单元格；摘要读取层同时过滤来源不一致的旧历史资产。版本链、版本差异和历史单价已进入 Excel 专用表，工作台已提供版本链/历史资产入口。上述实现不等同于跨独立项目库的企业级 global 知识中心，后者仍列为条件缺口。

## P0-02 失败样本与验收

最小反例是：项目有三期，先完整校核，再只重跑一期。当前结果表会撤下另外两期，但摘要如果仍返回 `verification.status = sufficient`，即属于 false-green。修复后必须同时满足：

- `periods_total = 3`、`periods_checked = 1`、`periods_unchecked = 2`；
- 期次总体状态不得为 `sufficient`，内部应降为不充分；
- 项目结论不得为“可形成项目结论”；
- 工作台、项目列表、Excel 和 Word 不得自行把局部状态显示为整体通过；
- 缺少当前有效结果时必须保留“校核不充分”或“不可形成项目结论”的限制。

## P0-01 证明模型验收

逐 Sheet 证明必须能回溯到文件、Sheet、范围和每一行分类，至少区分：明细、小计、合计、标题、说明/备注、空白、尾注、孤立数值、解析失败、待确认和未识别。证明必须把“识别为明细的行数”和“最终参与累计的业务行数”分开，不能因为金额缺失而以零补齐。

A/B 数值相等只能说明两条读取路径在当前行集上相等。若两条路径共享抽取行集，报告必须明确非独立；C 缺失、范围未证明或有未识别行时，期次只能是“校核不充分”。C Evidence 应直接包含控制值的文件、Sheet、行列、原文、选择规则和来源 Evidence。

## P0-03 合同不变量

同一项目输入改变后必须创建新合同。即使输入后来恢复到历史签名，也必须创建新的运行记录，不能重新激活旧合同或改写旧合同的创建时间、组件和失效时间。合同至少需要逐步纳入：文件清单与 SHA-256、Sheet/表头/范围、字段映射、期次与方向、清洗/匹配/异常规则版本、Decimal 精度与舍入、程序与 schema 版本、别名库版本、人工确认快照和适用范围。

## 暂不关闭的门槛

以下内容仍未关闭：真实案例黄金回归、WPS/Excel 四环境真机、Windows 原生构建、1/5/20 万行现场性能、签名/公证和异常退出恢复，以及跨独立项目库的授权知识中心。备份恢复与前向迁移已有自动化证据，但不等同于活动 schema downgrade。P2-01/P2-03 的数据库/API、Excel 专用表和工作台入口已实现，实际脱敏资产和 Word 中的字段级版本差异仍以 Excel 明细为准。`scripts/release_checklist.py` 会把自动化测试、黄金回归、性能、Office、迁移/恢复、签名、已知限制和未解决 P0/P1 统一生成 JSON/Markdown；`not_run`、`conditional` 和 `not_available` 均不得解释为通过。每项必须在对应证据产生后单独更新状态，不得用合成测试或静态扫描代替实机结果。
