# Jiadun（价盾）v0.1.24 — 合同事实确认生命周期预发行

## 本版定位

v0.1.24 是在 v0.1.23 基础上的合同事实确认生命周期版本（阶段 C-1，结构版本 v48），
也是一个预览候选。长期平台战略保持不变：macOS Apple Silicon 仍是 P0 主平台，
Windows x64 仍是 P1；共享业务核心保持跨平台，Windows 特有逻辑继续放在 `platform/`
层。本版不标记为正式生产版。

宪章要求"只有 confirmed 才能用于金额和控制规则"。本版把这条原则落到数据模型、
运行契约和界面上：抽取产出一律是候选，人工确认才是已确认事实，全程可追溯。

## 主要变化

### 合同事实确认生命周期（本版核心）

- 迁移 v48：`contract_facts` 新增确认状态字段；**历史事实无法证明经过人工确认，
  一律回填为候选**，不自动升已确认。
- 抽取产出的条款一律是候选（candidate）。新增确认服务：确认 / 拒绝 / 标记待复核
  三向流转；**推翻已确认或已拒绝结论必须填写理由**；每次流转写入
  `contract_fact_review` 审计 Evidence（前后值、操作者、理由）。
- 合同事实状态变化后按既有机制产生新的 Run Contract 签名：旧计算结果保留为历史，
  不再作为当前结论，重跑后恢复当前。
- Run Contract 门控：**被人工拒绝的条款不再进入运行契约**；候选条款仍随载荷输出
  并带状态标记（不静默、不冒充已确认）；新增确认情况汇总，界面与报告无需重算即可见。

### 风险语义（fail-closed 且不误报）

- 被拒绝的条款视为缺失：对应的"缺少付款/结算条款"等风险照常触发。
- 候选条款保持条款覆盖判定（不把存量项目打成一片"缺少条款"误报），但按文档给出
  "候选条款待人工确认"低级提示，提示不进入计算。

### 工作台界面

- 新增"合同条款确认…"对话框：按状态筛选（候选/待复核/已确认/已拒绝/全部），
  逐条确认或拒绝，推翻既有结论时理由必填；确认信息写入审计。

### 继承能力

v0.1.23 及之前的页级混合 PDF 提取边界、离线 RapidOCR 模型清单校验、资料中心、
备份恢复安全加固、Windows 工作簿所有权、fail-closed 历史合同门控等能力全部保留，
本版未修改这些子系统的业务逻辑。

## 升级影响（如实声明）

- 旧项目升级到本版后结构版本迁至 v48，合同签名变化会使既有计算结果退出"当前
  结论"（完整保留可查），重跑后恢复当前；迁移自动备份，失败可回滚。
- 候选语义不改变既有风险判定：存量项目不会出现风险条目突增。

## 安装与兼容

Windows x64 安装包与便携包为未签名构建物，下载前请核对同一 Release 的
SHA256SUMS.txt。不要将 `PENDING / NOT VERIFIED` 误读为已通过的真机能力，
也不要把预览候选当成交付生产结论使用。
