# Jiadun（价盾）v0.1.20 — 资料中心与异步导入预发行

## 本版定位

v0.1.20 是在 v0.1.19 基础上的资料导入可观察性增量版本，也是一个预览候选。长期平台战略保持不变：
macOS Apple Silicon 仍是 P0 主平台，Windows x64 仍是 P1；共享业务核心保持跨平台，
Windows 特有逻辑继续放在 `platform/` 层。本版不标记为正式生产版。

本版解决的是“资料进来后看不见、导入大文件时界面像卡死、方向/类别不清楚、解析失败
还继续往下算”的流程问题；不把尚未完成的 OCR、合同条款自动识别或业务规则算法包装
成已完成能力。

## 主要变化

### 资料中心和明确分类

- 新增资料中心，已导入文件统计可点击进入文件清单；清单展示文件名、分类、方向、
  类型、大小、短 SHA-256、导入时间和状态，详情可查看完整 SHA-256、来源副本和技术说明。
- 导入前由用户选择资料类别，不根据文件名猜业务含义。分类覆盖：对上中标及投标文件、
  对上合同（含补充协议）、对上框架/管理性协议、会议纪要/补充约定、其他协议、
  对上结算资料、对上竣工结算/终审（审计/审核）报告、对上收款台账、对下支付台账、
  对下物资结算和对下分包结算。
- 对上终审/审计/审核报告登记为 `control_candidate`，表示“待确认的控制基准候选”；
  它可以在后续作为对比上限的证据来源，但本版不会自动把它当作合同额或封顶值。
- 框架/管理性协议（例如管理费、协作费比例）和会议纪要当前登记为 Evidence 资料；
  本版不自动把 3%、5% 等文本转成金额规则。

### 后台导入与 fail-closed

- 文件、文件夹和拖拽导入改由后台工作线程执行，并使用独立数据库连接，避免大文件读取
  阻塞主界面。
- 每个文件单独记录 `registered/processing/parsed/needs_review/pending_ocr/failed` 等
  状态；一个文件失败不会把其他文件伪装成成功。
- 扫描型 PDF 或表格解析无法可靠识别时，停在 `PENDING/OCR 待处理`，不继续做自动匹配、
  结算分析或报告导出；原始文件仍只读，测试副本和导出物位于独立工作区。
- 合同和结算导入保留显式资料类别；旧的程序调用路径仍可工作，但 UI 入口不再同步阻塞。

## 验证结果

### 代码与普通回归

- Windows Python 3.12 x64 项目环境：`ruff check src tests` 通过。
- 完整普通测试（排除需要长时间资源占用的 `test_performance_benchmark.py`）明确退出码为
  `0`；性能测试入口明确退出码为 `0`。ZIP 重名测试输出的 `Duplicate name: project.db`
  是故意构造重复 ZIP 条目的测试警告。
- golden regression 与发布一致性检查在“无脱敏真实黄金登记”模式下只能得到条件状态，
  不代表生产发布门槛已关闭。

### 本机真实项目资料测试

- 仅选择 5 个匿名样本的隔离副本运行，未对原文件保存、覆盖、重命名、移动、删除、转换
  或写入批注/公式/隐藏数据。
- 样本包含 `.xlsx` 与 `.xls`、多 Sheet、隐藏 Sheet、公式、合并单元格、外部链接和中文/空格
  隔离路径；最大副本为 64,858,270 bytes，最大样本有 32 个 Sheet，其中 25 个隐藏。
- 5 个样本均完成只读结构检查和导入尝试；解析无法确认的结果均为 `PENDING`，没有自动
  分析、强制匹配、补 0 或导出错误结论。
- 5 个原始文件测试前后 SHA-256、大小、修改时间全部一致；真实资料没有写入 Git。
- 真实 Microsoft Excel/WPS 打开关闭仍为 `PENDING / NOT VERIFIED`，不能用 openpyxl、mock
  或 WPS 结果替代 Excel 真机 PASS。
- Windows Excel、WPS、macOS Excel 的真机打开/关闭仍分别需要专项验证；1万、5万、20万行
  完整导出、代码签名和 macOS 公证都仍是发布门槛，不能将预览候选写成正式生产版。

## 尚未完成和风险边界

- 扫描 PDF OCR 尚未集成；因此“PDF 最靠谱、先 OCR 再识别”仍是下一阶段工作，当前只能
  留在待处理状态。
- 合同、补充协议、框架/管理协议、会议纪要的关键条款识别、付款比例/管理费比例规则和
  风险报告仍需 Evidence 驱动的抽取与人工确认；AI 不参与金额决定。
- 对上合同清单、对上终审/审计清单、对上实际结算之间的“参考/控制基准/结果”分层，
  以及把终审清单作为上限候选的冲突处理算法尚未实现。
- 50k 完整 Excel 导出仍未完成；此前同环境 before/after 均为 `TIMEOUT / INCOMPLETE`，
  不给出虚假的改善倍数。真实 Office、macOS Excel/WPS、权限异常和 reparse point 真机
  专项仍待验证。

## 安装与兼容

源码运行仍为 Python 3.12 + `uv sync`。macOS Apple Silicon 继续作为主平台；Windows x64
包和任何未来构建物必须以同一 Release 的校验和及真实平台验证结果为准。下载包前请阅读
本说明，不要将 `PENDING / NOT VERIFIED` 误读为已通过的真机能力。
