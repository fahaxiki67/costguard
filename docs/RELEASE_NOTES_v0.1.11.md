# Jiadun（价盾）v0.1.11 — 证据边界与只读工作台预发行

## 本版定位

v0.1.11 是 v0.1.10 证据闸门深化版本的维护性预发行版和预览候选，针对独立复核发现的
源文件副本、工作台读取副作用、Word 当前/历史 Evidence 计数和许可证文档
口径问题继续收口。本版仍是 Preview/Prerelease，只适合合成或已经授权脱敏
资料的试用、规则验证和流程反馈，不代表正式结算、付款、责任、审批或经营结论。

## 主要变化

- Run Contract 的源文件组件现在绑定解析器实际消费的 stored_path。对新合同
  记录的存储副本按块重新计算 SHA-256；副本被覆盖、重定向、删除或无法读取
  时，当前读取面 fail-closed。登记的 SHA-256 必须是合法 64 位十六进制且与
  副本内容一致，文件大小必须是非负整数且与副本实际字节数一致；非法旧库或
  外部 SQL 数据不能形成当前合同。
- 旧合同如果没有 stored_path 绑定，不再作为当前结果使用；受控重跑会创建
  包含完整副本路径的新运行。受控项目搬迁在内容未变时使旧运行退出 current，
  并创建新的运行合同。
- build_report_model(read_only=True) 贯通工作台顶部状态、项目概览、版本/历史
  资产和成果状态刷新，查看状态不会写入派生清洗标记，也不会清除运行级
  fail-closed 侧车。
- Word 管理层摘要明确区分“当前范围 Evidence”和“历史 Evidence”；历史记录
  继续保留，但不参与当前金额、Finding 数量或项目结论。
- current_scope() 在返回任何异常、匹配、汇总或 Evidence 范围前复核运行级源副本
  闸门；副本漂移时返回空范围。导出登记拒绝非当前 Run Contract 签名，并在写入
  事务内再次复核合同和源副本，避免把历史成果登记成 current。
- Architecture 的 ADR-009 与已接受的 Apache-2.0 许可证决策保持一致，并明确
  对 AGPL 项目只参考公开设计、未经审查不复制代码。

## 计算、证据和 AI 边界

- 金额、数量、单价及差额继续全部使用 Decimal，业务计算不使用 float。
- 原始文件永不修改；导入副本、Sheet、行列和计算过程继续通过 Evidence 追溯。
- 缺失资料保持“待补资料”，不可比保持“不可比”，不以 0 补齐、不强制调平。
- AI 只可辅助语义候选、条款分类和文字解释，不承担金额计算、最终匹配、自动
  补缺、正式结论或责任判断。

## 候选验证边界

候选发布必须重新执行自动化测试、Ruff、迁移/备份恢复、异常退出、取消机制、
黄金回归、发布一致性、安装包隐私和产物哈希检查。黄金回归中的合成案例可用于
验证执行器，真实脱敏案例数量为 0 时只能条件通过。

以下外部门槛仍需现场证据：

1. WPS macOS、WPS Windows、macOS Excel、Windows Excel 的打开、公式重算、
   中文字体、筛选、打印区域和 Evidence 跳转。
2. 1万、5万、20万行的导入、搜索、异常、匹配、校核、Excel 导出、进度、取消、
   数据库一致性和半成品清理。
3. Developer ID 签名、Apple 公证、跨系统安装和异常恢复。
4. 经授权脱敏的真实工程黄金回归及金额/匹配差异解释。

自动化现场记录：当前候选全量测试 580 项通过，Ruff 和差异检查通过；合成黄金
回归 1 项通过，真实黄金案例 0 项。源副本闸门、current_scope 历史隔离和导出
登记事务闸门已由独立复核确认通过。普通导入副本为只读，但在最终文件检查与
SQLite 写入之间仍保留极窄的文件级竞态边界；需要对抗恶意并发替换时，应升级
为不可变输入快照或文件描述符级校验。

关闭以上门槛前，v0.1.11 不能标记为正式生产版。

## 安装和兼容

macOS Apple Silicon 预发行资产：

Jiadun-0.1.11-macos-arm64.dmg

下载后使用同一 Release 中的 SHA256SUMS.txt 校验。当前 DMG 为 ad-hoc 本地
签名且未完成 Apple 公证，首次启动可能需要在“应用程序”中右键选择“打开”。
源码运行仍为：

uv sync --python 3.12
uv run jiadun

旧 costguard 图形命令继续作为迁移兼容入口。GitHub 仓库地址、历史 tag、旧
项目目录和旧导出文件保留原名称；升级不会删除、覆盖或移动原始工程资料。
