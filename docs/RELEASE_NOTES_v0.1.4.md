# CostGuard v0.1.4 — 工作空间持久化修复

本版本修复一个会让项目记录在应用重启后从列表中消失的问题。问题只影响项目发现路径，
不会删除 `project.db`、导入副本或导出成果。

## 修复内容

- 新建项目时选择的自定义工作空间会写入软件配置。
- 通过「打开项目目录…」打开项目后，CostGuard 会记住项目所在的工作空间。
- 项目列表同时扫描默认工作空间和已记住的工作空间，并按数据库路径去重。
- 刷新项目列表只读取项目概要，不执行数据库迁移，也不修改工程数据。
- 项目目录被移动后，以当前发现或选择的实际目录打开，不再依赖数据库中的旧路径。
- `settings.json` 采用原子替换，应用中断时不会留下半截配置文件。

## 已受影响项目的恢复方法

如果升级后仍有项目未显示：

1. 点击项目列表页的「打开项目目录…」。
2. 选择包含 `project.db` 的项目目录。
3. 项目成功打开后，CostGuard 会记住上一级工作空间；以后重启会自动显示该工作空间内的项目。

不要新建同名项目，也不要移动、覆盖或删除原项目目录。恢复动作只登记路径，不复制或改写原数据库。

## 验证结果

- 230 项自动化测试通过，`ruff` 检查通过。
- 使用实际遗留项目的备份副本完成 schema v3 → v5 升级验证。
- 升级前后保持不变：2 个源文件、4 个结算期次、32 条清单、45 条异常、45 条证据。
- 导入副本的 SHA-256 升级前后一致，数据库完整性检查结果为 `ok`。
- 数据库迁移前自动生成备份；测试结束后已清理可再生临时目录。

## 安装说明

安装包面向 macOS Apple Silicon。该版本使用 ad-hoc 本地签名，尚未进行 Apple Developer ID
签名或公证。首次启动可能需要在 Finder 中右键点击 CostGuard.app，再选择「打开」。
