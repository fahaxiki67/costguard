# Jiadun（价盾）v0.1.36 — 多分包有效数量与分楼栋核对

预览候选 / Prerelease。完整生产验收仍待真实资料和目标环境验证。

- 分包文件独立保存，同名“第 1 期”不混入同一期次；同一文件的同业务期多楼栋工作表复用期次。后台导入与人工工作表确认使用相同隔离规则。
- 新增数量上下文，明确合同、单位、业务期号、合同/结算、增量/累计、工作口径和修订替代。旧资料保持待确认。累计 100→180 的有效量为 180；明确修订 100→120 后有效量为 120。
- 多家分包同对象、同口径的有效结算量合并，对上合同量和对上已结算量分别比较，并列明各单位贡献。全项目未超不会掩盖单楼栋超量。
- 新增“工程量控制台账”和“行口径确认”入口。固定单位换算沿用 v0.1.34；人工跨量纲换算必须登记依据并确认。一致单栋来源按明确规则自动接受；冲突待确认，未知/组合范围不摊分。
- 缺量、缺单位、待确认范围、未明确的多上游基准、冲突版本阻断通过。缺失不补零，不按文件导入先后猜最终版本。
- Excel 导出控制台账、分包贡献、有效分项、逐行来源及待确认范围；Word 摘要使用同一计算服务。数量精确值保留文本，避免小量显示成 0.00。原始期次累计表保留为原始统计，不能替代有效数量台账。

v0.1.35 为未发布候选，本版包含其全部工程量控制改动，并补充：

- 从清单文本、工作表和原文件名逐行识别楼栋。一致的单栋来源采用规则自动接受并保留依据；矛盾、未知及组合范围进入待确认，保留全项目量。
- 修正“十一号楼”“二十号楼”和区间/并列楼栋的解析边界。不支持的写法保留待确认。
- 名称、非空项目特征、已验证标准量纲和已确认工作范围一致时，来源编码不同也可按明确规则归并；原编码与规则依据保留在来源。
- 本期发生清单不要求每期重复出现，其他合同也不要求包含同一清单。最新累计资料缺项和未确认覆盖继续待核实。

- 两平台安装包显式携带运行版本所需的元数据，避免安装包版本正确但运行记录显示未知；仅打包 METADATA，不带入开发机安装来源。

## 核对示例

同一项目和计量口径：对上 1 号楼 1000、2 号楼 800；对下 A 为 600/200、B 为 500/300、C 为 0/100。
1 号楼合计 1100，超 100；2 号楼合计 600，未超；全项目合计 1700，未超 1800。楼栋和全项目结论分别保留。

## 升级与回退

本版迁移至 schema v56，升级前自动备份；只追加数量上下文，不重写原件及既有清单事实。旧混合来源期次不能通过一次确认归到某个合同，应在新项目中按来源隔离重新导入原件并核清范围。
回退 v0.1.34 前需恢复升级前备份；旧程序不能读取 v56 数据库。升级后新增的原件和确认记录须另行备份保留。不要删除原项目。

操作步骤见[三分钟上手](QUICKSTART_zh-CN.md)。当前已登记期次身份字段没有直接修改入口；登记错误须保留原项目，在独立项目重新导入登记。行口径可重新登记并显式确认。
