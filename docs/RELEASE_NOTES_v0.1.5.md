# Jiadun（价盾）v0.1.5 — 真实结算书识别 + 人工确认 GUI（macOS，历史版本）

> 兼容说明：本文记录 v0.1.5 当时的发布内容，当时产品名称为 CostGuard；现行产品名称
> 为 Jiadun（价盾）。历史项目路径、应用名称和远端资产按当时事实保留，不表示远端资产
> 已经改名。

本版本解决 Mac 用户最痛的问题：**真实结算书导入后全部卡在"待人工确认"、GUI 无路可走**。
与 Windows 版共享同一核心引擎、数据模型、测试与 UI；全部纪律不变
（缺失不填零、金额 Decimal、对上对下隔离、原始文件只读、证据链与人工确认门控）。

## 本次新增

- **被门控工作表的人工确认 GUI**（issue #5）：导入后对待确认页可一键打开
  "人工确认清单页"——区分"表头歧义待复核/无表头"两种状态、预填自动识别的
  候选列映射、指定方向期次与 8 字段列映射、表头行范围，然后
  "按结算清单抽取"或"仅存证（非结算角色）"；原因必填、全程写审计日志。
- **国标表式识别**（表-08 分部分项清单/表-12-3 等）：三层表头（"金额（元）"
  横跨综合单价+合价、"其中"横跨定额费列）正确解析为标准列映射；表标题行
  不再被误当字段；分部标题行不再被吸收成垃圾明细。
- 小计词补充"本页小计/本页合计"，小计标签的排版空格（"小     计"）不再逃逸识别。
- 汇总表（E.6 型）不再被误判为键值对表单，正确进入"待人工角色确认"。

## 真实效果（内部真实语料对照，技术测试记录）

- 一本 229 个 Sheet 的标准竣工结算书：自动解析从 **0 页 → 25 页 / 1,211 行明细**
  （1,096 行带金额），表单误判 45 → 29；剩余复杂页（表-09 综合单价分析、
  G.1–G.3 汇总页）如实保留人工确认，由新 GUI 逐页处理。
- 262 项自动测试全绿；安装→启动→退出→重启回归通过；匿名演示数据端到端通过。

## 签名边界（如实说明）

- DMG 为 **ad-hoc 本地签名、未公证**：首次启动如提示"无法验证开发者"，
  在应用程序文件夹**右键 → 打开**；不承诺完全不出现 Gatekeeper 提示。

## 升级与数据安全

- 工程数据在历史路径 `~/Documents/CostGuardProjects`，与程序分离，升级/卸载不影响。
- 自动结果不等于已批准业务结论；扫描 PDF/OCR 仍未实现（会明确提示）。

  issue #4（A/B 同源行集独立性）一并处理。
- 表-09 综合单价分析等多层表头页仍需人工确认后使用。
