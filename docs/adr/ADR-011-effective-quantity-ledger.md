# ADR-011：有效数量与原始期次统计分开

状态：v0.1.35 预览候选。日期：2026-10-01。

结算数量需同时明确方向、合同、单位、业务期号、合同/结算类型、增量/累计模式、工作计量口径和有效版本。原有按方向递增的内部期号不能代表不同分包各自的“第 1 期”。直接累计全部原始期次不能满足多合同与修订版本核量。

采用既有 SQLite、Decimal、Evidence、审计日志及 Run Contract，不增加服务或外部依赖。迁移 v56 只追加 `quantity_period_context`、`quantity_line_context` 两个表和索引。原始期次和清单行保留。旧资料的上下文保持待确认。

`quantity_control.build_quantity_ledger` 为界面、Excel、Word 的共同数量事实服务。增量按有效期相加，累计仅取最新有效业务期快照；最新期缺项保持待补，不能回填旧量或补零。修订必须声明替代关系，旧行及证据不删除。同身份有效版本冲突保持待确认。自动身份保留编码/名称命名空间、名称、特征与标准量纲；人工标准键不能绕过特征或量纲检查。

对上合同量与对上已结算量分别作为基准。至少提供一种可用基准即可按该基准核对；总体结论列明实际使用的基准。已提供但缺量或待确认的资料不能忽略。对下不同合同的同对象、同工作口径数量合并，保留各单位贡献。全项目和各楼栋独立判断；未知或组合楼栋范围不摊分到单栋。多个上游合同向同一控制范围贡献数量时，先要求明确选择或去重，不能默认叠加。

同量纲换算沿用既有单位服务，跨量纲换算须人工提供系数、目标单位与依据并确认。来源保留文件、工作表、行号、原单位/原数量、系数、标准行数量、楼栋范围和是否计入。上下文、状态和替代关系进入运行指纹；变更使旧运行退出当前结果。

旧累计表仍作为原始期次统计，包含全部版本，不能作为有效数量结论。导出明确说明此边界；新数量表缺量或不可比时留空，来源逐行列示，避免长 JSON 单元格截断来源。

迁移沿用升级前备份、事务和失败恢复。回退旧程序前须恢复升级前数据库备份，旧程序拒绝打开 schema v56；升级后新增的资料与确认记录须另行保留。真实资料、四种 Office 环境、大规模现场性能与签名公证不因合成检查通过而视为完成。
