# Jiadun（价盾）v0.1.17 — 可信度与本地使用流程预发行

## 本版定位

v0.1.17 是 v0.1.16 之后的阶段性预发行版和预览候选。本版把当前已经完成的本地
导入、解析保真、A/B/C 校核、黄金回归、匹配质量基准和发布门禁改动整理为一个可下载
版本，便于继续使用和收集真实反馈。本版不代表正式生产版，也不替代真实工程资料、
WPS/Excel 四环境或签名公证验收。

## 主要变化

### 本地资料导入流程

- 首次启动保持空白，不自动加载模拟项目、清单或计算结果。
- 支持选择单个或多个 Excel/CSV 文件、递归选择资料文件夹，以及直接拖入文件或文件夹。
- 导入后保留文件、Sheet、字段候选和数据预览；字段和范围需要人工确认后才进入计算。
- 导入失败保留明确原因，并允许重新选择、删除失败项或重新开始；原始文件只读，项目内只保存可追溯副本。

### 解析与结算可信度

- 增加源工作簿 Sheet 目录、物理行、有效单元格和坐标指纹盘点，并与解析网格交叉核对，
  用于发现漏行、跨 Sheet、重复表头、合计行污染等结构问题。
- A 路径从清洗明细汇总，B 路径直接从不可变 `raw_cells` 独立扫描，C 路径读取源表
  明确的合计或期次控制值；路径不独立、范围无法证明或控制值缺失时保持 fail-closed。
- 新项目首次分析会先物化当前期次聚合，避免“刚导入就无法校核”；这不会放宽
  A/B/C 的独立性门槛，也不会用 0 补缺或人为调平。
- 解析物化和覆盖证明使用外层事务，失败后只保留失败批次和 Evidence，不留下半成品业务结果。

### 黄金回归与匹配基准

- `scripts/golden_regression.py` 继续只读比较，不自动更新黄金基线；金额、行数、匹配、
  异常或 Evidence 变化会产生明确差异。
- 新增 `scripts/matching_benchmark.py`，以文件 SHA-256、Sheet 和物理行组成稳定项目项身份，
  只对人工真值计算 precision、recall、F1、误报和漏报；没有人工真值时保持 `PENDING`。
- 公开仓库不收录未脱敏真实资料。当前真实黄金案例数量仍为 0，合成案例不能替代真实项目验收。

### 性能与跨平台现场记录

- 性能基准的取消/异常终态现在保留规模、阶段、原因和时间；发布清单还会复核规模与
  方向行数、各阶段耗时、生成/导入/分页计数、现场保留、运行包哈希以及真实 XLSX
  ZIP 结构，拒绝空结果、缺步骤或缺终止证据的现场。取消状态只能标记为条件状态，
  不会被解释为通过。
- Windows 隐私审计脚本已修复默认 cp1252 控制台打印中文导致的崩溃；修复后的 Windows
  原生打包仍需重新运行确认，不能用本地 macOS 测试代替。
- 界面字体继续按平台选择 PingFang SC、Microsoft YaHei UI 或 Noto Sans CJK SC，
  不在业务计算中引入浮点数。

## 安装与数据安全

- macOS Apple Silicon：`Jiadun-0.1.17-macos-arm64.dmg`。首次启动可能需要在应用程序中右键选择“打开”。
- 源码运行：安装 Python 3.12 和 uv 后执行 `uv sync --python 3.12`，再运行 `uv run jiadun`。
- 所有项目数据保存在本地用户选择的工作空间，原始文件不被覆盖；缺失资料显示“待补资料”，
  不可比项目显示“不可比”。`local_private_data/` 和任何未授权的外部移动存储资料均不进入公开发布物。
- 下载后使用同一 Release 中的 `SHA256SUMS.txt` 校验文件完整性。该校验和不等同于代码签名或公证证明。
