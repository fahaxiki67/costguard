# Jiadun（价盾）v0.1.25 — 确认生命周期与控制规则预发行

## 本版定位

v0.1.25 是在 v0.1.24 基础上连续推进四个确认/控制子系统的预览候选（结构版本 v51）：
合同事实确认生命周期（v48）、PDF 逐页人工对照复核（v49）、对上控制基准候选与上限
比较（v50）、框架/管理性协议费率规则（v51）。长期平台战略不变：macOS Apple Silicon
仍是 P0 主平台，Windows x64 仍是 P1。本版不标记为正式生产版。

本版主线是把宪章三条硬原则落到数据模型与界面：**只有 confirmed 才能用于金额和控制
规则**、**费率不是一个百分比**、**控制基准不自动挑选**。

## 主要变化

### 合同事实确认生命周期（v48）

- 抽取条款一律候选；确认/拒绝/待复核三向流转，推翻已确认或已拒绝结论必须填写理由；
- 每次流转写入 contract_fact_review 审计 Evidence（前后值、操作者、理由）；
- 被拒绝条款退出运行契约；候选带状态标记与确认汇总；历史事实回填 candidate。

### PDF 逐页人工对照复核（v49）

- 含 OCR 页的合同停在 needs_review；用户对照只读原件逐页核实（对照依据必填）；
- 全部应复核页核实后才允许文档转 parsed；原生文本页不可复核，
  pending_ocr/failed 文档须先重新解析；条款仍按条款级确认。

### 对上控制基准候选与上限比较（v50）

- 终审/审计报告类资料的已确认金额条款可登记为控制基准候选；确认必须给出
  范围/税口径/版本核对依据；
- 上限比较固定五态：PASS / FAIL（只报超出金额，不认定违规或责任）/ PENDING /
  INCOMPARABLE（税口径或范围明确不同）/ CONTROL_CONFLICT（多个有效基准并存且无
  supersedes 替代关系）；取代关系必须显式声明；
- 对上结算结果 = 对上期次明细合计（Decimal，小计行导入时已排除）。

### 框架/管理性协议费率规则（v51）

- 触发词句级扫描：句内每个百分比各成一条候选（3%/全角％/3 个点/百分之三），
  同句去重；公式型比例（如"按结算金额的（9-X）%"）产出"需人工解读"候选，
  不静默丢弃；
- 确认必须人工设定计取基数类型与说明——"按结算价 3%"与"按不含税价 3%"不是
  同一条规则；公式型候选确认时必须人工填写比例；候选未确认不得试算；
- 试算为 Decimal 确定性计算（round2），支持上限封顶/下限兜底；
- 真实框架协议语料实测验证（详见 CURRENT_STATE_AUDIT）。

## 验证结果

### 已通过

- 全量 pytest 以最终退出码收口；新增单测覆盖迁移回填、状态流转、五态比较、
  费率抽取/确认/试算与对应 UI（offscreen）。
- 真实框架协议（民权县高中部建设合作框架协议终稿）隔离副本实测：140 段抽出
  19 条候选（18 数值 + 1 公式型），唯一比例与人工核对一致；测试前后原件哈希
  逐字节一致；真实内容未进入 Git。
- ruff、黄金回归（合成案例 PASS）、发布一致性检查、Windows x64 打包链、
  macOS arm64 CI 构建。

### 仍是 PENDING / NOT VERIFIED

- 真实工程扫描 PDF 的 OCR 质量回归与页级复核实机闭环（脱敏黄金样本登记为 0）。
- 费率基数与对上/对下期次合计的自动关联；费率规则接入 Run Contract 载荷。
- 控制基准比较结论接入审核问题中心与报告导出；结构化 scope 字段。
- 真实 Microsoft Excel/WPS（Windows 与 macOS）真机专项：Windows Excel、
  macOS Excel 的打开/重算/筛选/超链接/打印/保存/再打开核对仍待验证。
- 1万、5万、20万行完整导出基准的同环境实测；Windows 代码签名与 macOS 公证。

## 升级影响

旧项目打开后自动迁移到 v51（迁移前自动备份）；v48 起合同签名变化会使既有计算
结果退出"当前结论"（完整保留可查），重跑后恢复。候选语义不改变既有风险判定。

## 安装与兼容

源码运行仍为 Python 3.12 + `uv sync`。下载前请核对同一 Release 的 SHA256SUMS.txt。
不要将 PENDING / NOT VERIFIED 误读为已通过的真机能力。
