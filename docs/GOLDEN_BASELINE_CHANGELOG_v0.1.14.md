# v0.1.14 黄金基线变更记录

本文件记录 `tests/golden/cases.json` 在 v0.1.14 候选中的逐字段变化。黄金回归只读比较，
不会自动把运行结果写回基线；任何基线变更都必须同时有原因、可复算证据和人工确认。

## 比较对象

- 旧基线：v0.1.12 标签提交 `38db0ef` 中的
  `tests/golden/cases.json`。需要复核时可执行
  `git show 38db0ef:tests/golden/cases.json` 重新取得，不依赖当前工作树。
- 新基线：当前 v0.1.14 候选的 `tests/golden/cases.json`。
- v0.1.13 的 Windows 符号链接测试守卫和 demo 跨平台确定性修复不改变解析、计算和黄金
  金额；本文件记录的字段变化来自 v0.1.14 可信度闸门收紧。

## 逐字段差异

| 字段 | v0.1.12 旧基线 | v0.1.14 候选 | 变更原因与证据 |
| --- | ---: | ---: | --- |
| `automatic_recognition_count` | 7 | 5 | 新增重复表头、公式缓存、筛选/合并、隐藏可见性和内部空白范围闸门后，演示资料中只有 5 个 Sheet 可由系统自动确认；第 1 期公式缓存和第 3 期数据区空白行均转为待复核。 |
| `pending_sheet_count` | 1 | 3 | 同上：1 个原待确认汇总 Sheet，加上第 1 期公式结构缺口和第 3 期内部空白范围缺口。 |
| `evidence.current_count` | 122 | 126 | A/B 原始网格独立扫描、C 原始控制单元格包装和覆盖证明新增 4 条当前运行 Evidence；来源 Evidence 保持只读。 |
| `evidence.by_kind.line_item_source` | 53 | 57 | 新增的 4 条可定位明细来源 Evidence；金额及匹配关系未因计数调整而被调平。 |
| `run_contract.schema_version` | 43 | 45 | v0.1.14 使用覆盖证明、公式/筛选/合并结构元数据和当前运行包装所需的数据库迁移。旧运行结果不会冒充当前结果。 |

## 验证记录

候选基线必须满足：

1. `uv run python scripts/golden_regression.py --json` 中合成案例 `mismatch_case_count=0`；
2. `uv run pytest -q tests/unit/test_golden_regression.py` 通过，且执行器未写回登记表；
3. 任一金额、有效行数、匹配关系、异常项或 Evidence 关键字段发生变化时，先补充本表和
   证据，再由人工决定是否更新黄金值；
4. 脱敏真实案例仍未登记时，黄金回归只能作为合成/框架验证，不能宣称生产覆盖。

v0.1.14 的空白行门控采用保守规则：表头后的前置空行、明细与控制行之间的空白/说明行
均保留为范围证据，当前版本不会自动将其视为已覆盖；需要人工确认数据范围并覆盖表头后
的全部非空物理行，才能吸收隐藏可见性风险。人工确认明确数据范围后，系统保留操作人、
时间、修改前后范围和原因，并重新绑定当前 Run Contract。重复表头、表头前疑似业务行、
解析失败等其它结构风险不会被该确认覆盖。
